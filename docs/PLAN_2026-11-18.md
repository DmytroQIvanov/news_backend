# Improvement plan

Paths use **B** = `C:/NEWS-PROJECT/opportunity-radar-starter` and **M** = `C:/NEWS-PROJECT/mobile`.

This is a static, read-only audit. Backend and mobile typechecks passed. Mobile lint reported **57 errors and 94 warnings**. Backend `npm test` was not run because its build step writes files. Phone performance and visual measurements below are acceptance targets, not observed results.

**Effort:** S = 1–2 engineer-days; M = 3–5; L = 6–10. Each batch is a complete release, requiring no work from a later batch. Keep API changes additive and migrations reversible.

**Release gate for every batch:** backend `npm test`; mobile `npx tsc --noEmit` and `npm test`; no new lint errors. Run Python tests when knowledge code changes, using disposable databases and mocked providers. Retain the existing publication gate during outages and quota exhaustion.

## Batch 1 — Enforce publishing safeguards and operating limits

### P01 — Apply one publication policy across every news surface

- **Why / evidence:** `B/src/news/news.controller.ts` accepts any `kb_event_id` through `FEED_QUALITY_GATE_SQL`, bypassing its source-count condition. Legacy eligibility counts `cluster_sources` entries. `B/src/news/objectivity.controller.ts` builds briefs from published rows without the same gate; manual publishing changes status directly.
- **Exact change:** Extract a shared eligibility policy requiring AI authorship, published status, and at least two usable, independent cited origins. Apply it to feeds, briefs, recommendations, topics, top stories, and audio selection. Recheck eligibility at publication; preserve rejection status. Return separate document and independent-origin counts.
- **Acceptance test:** Fixtures containing raw RSS, one-source KB articles, duplicate URLs, syndicated reports, rejected articles, and valid two-origin articles produce identical eligibility across surfaces. Only the valid article appears.
- **Effort:** M.
- **Risk:** Feed volume may drop as existing false positives disappear; expose reasons through P05.
- **Dependencies:** None.

### P02 — Require a successful review of the final article

- **Why / evidence:** In `B/src/kb/kb-editorial.service.ts`, review failures are caught without forcing review; missing verdicts also do not block publication. Applying some patches can change a verdict to `ok`. Expansion happens inside `publish()`, after review; `rescueShort()` can restore `checks_passed`.
- **Exact change:** Persist explicit review states and require one valid verdict per expected event. Missing, malformed, failed, or unresolved reviews must hold the candidate. Re-review changed passages after patches or expansion, and retain unresolved issue IDs. Rescue must never clear unrelated review holds.
- **Acceptance test:** Reviewer timeout, missing event, partial patch, unsupported expansion, and rescue of a rejected candidate all remain unpublished. A fully reviewed final version publishes after translation.
- **Effort:** M.
- **Risk:** More candidates wait during provider outages; retain the last approved published version.
- **Dependencies:** P01.

### P03 — Unify quotas across Python, NestJS, and provider accounts

- **Why / evidence:** `B/src/common/llm-budget.ts` has the stated Gemini limits, but `B/knowledge/kb/video/gemini.py` retains older defaults. NestJS falls back to process-local counters when PostgreSQL fails. `B/src/common/llm-router.ts` tracks OpenRouter usage per model despite its account-wide allowance.
- **Exact change:** Use one versioned quota configuration: 500/20/20/20 for the supplied Gemini allowances; Gemma has no daily cap but retains concurrency and rate limits. Share atomic reservations across runtimes, retries, restarts, and OpenRouter models. Defer budgeted calls when accounting is unavailable. Reserve capacity for verification, corroboration, and translation before decorative tasks.
- **Acceptance test:** Concurrent Python/Node reservations cannot exceed each daily allowance; retries count; restart preserves usage; database failure sends no unaccounted calls. Reject paid OpenRouter targets under the free-only configuration.
- **Effort:** M.
- **Risk:** Incorrect model aliases could block useful fallbacks.
- **Dependencies:** None.
- **Unattended restriction:** Changing credentials, enabling billing, or raising paid-service limits requires human action.

### P04 — Provide a measured deployment profile for the 1 GB VM

- **Why / evidence:** `B/compose.server.yaml` defaults PostgreSQL `shared_buffers` to 1 GB, gives NLP a 3 GB limit, and configures a 2 GB video tmpfs. `B/knowledge/kb/config.py` defaults to eight collector threads and embeddings. `B/oracle/compose.yaml` describes a separate helper deployment, so actual service placement needs verification.
- **Exact change:** Document the deployed topology and create a small-machine profile with bounded PostgreSQL memory/connections, Node heap, collector concurrency, and background-job concurrency. Keep heavy NLP, embedding, video, and maintenance workloads off the always-on VM unless measured to fit; schedule them on an existing separate machine where necessary. Exclude heavyweight services from default startup.
- **Acceptance test:** A 24-hour representative workload stays below 800 MiB aggregate resident memory, causes no OOM restarts or sustained swapping, and continues ingesting and serving feeds. Record throughput with embeddings disabled.
- **Effort:** M.
- **Risk:** Reduced analysis throughput or multilingual clustering quality.
- **Dependencies:** None.
- **Unattended restriction:** Live service relocation, database configuration changes, and deployment require operator review.

### P05 — Make stalled coverage and failed safeguards observable

- **Why / evidence:** `B/src/health/health.controller.ts` mainly measures connectivity and row totals. `isKbEditorialActive()` in `B/src/kb/kb-editorial.service.ts` treats a recent NLP start as evidence of health. `B/.github/workflows/check.yml` builds and typechecks without running `npm test`.
- **Exact change:** Report last successful worker completion, stage backlog/oldest age, publication-block reasons, translation failures, quota deferrals, and memory pressure. Distinguish “running,” “progressing,” and “stalled.” Add backend tests to CI and make required Python quality-test skips visible failures in the quality job. Keep detailed diagnostics authenticated and public health responses small.
- **Acceptance test:** A worker that starts but never finishes becomes stalled; a quota outage is distinguished from missing sources. CI catches a deliberately failing publication regression. Diagnostics contain no secrets or article bodies.
- **Effort:** M.
- **Risk:** Expensive status queries could burden the VM; cache aggregates.
- **Dependencies:** P01–P04.

**Batch exit:** Publishing safeguards and resource controls work without any mobile upgrade.

## Batch 2 — Strengthen evidence and increase useful coverage

### P06 — Use consistent evidence identities and validate event clustering

- **Why / evidence:** Python counts evidence roots and owner groups in `B/knowledge/kb/graph/importance.py`; corroboration uses hostname-derived roots in `B/src/kb/kb-corroboration.service.ts`. `B/src/kb/kb-dossier.ts` adds accepted research counts to stored event counts using another deduplication path.
- **Exact change:** Define shared publisher, owner-group, originating-report, and document identities. Replace hostname heuristics with reliable registrable-domain handling. Count the union of eligible origins across collected and researched documents. Add bilingual clustering fixtures for repeated incidents, syndicated reports, and same-topic/different-event reports; retain match explanations.
- **Acceptance test:** Reuters plus three reprints counts once; duplicate research and collected documents count once; independent reporting counts separately. Ukrainian/English reports of one event join, while separate attacks on successive dates remain separate, including the low-memory mode.
- **Effort:** L.
- **Risk:** Count changes can affect eligibility and clustering.
- **Dependencies:** P01, P04, P05.
- **Unattended restriction:** Existing-corpus reclustering, entity merges, or bulk lineage rewrites require a reviewed dry run and backup.

### P07 — Validate claims against supporting passages and preserve disagreements

- **Why / evidence:** `B/src/kb/kb-editorial.service.ts` checks numbers against the whole dossier, exempts years/small counts, and only flags more than three unknown numbers. `B/knowledge/kb/graph/facts.py` can suppress numeric disputes when primary evidence exists or values are growing counts.
- **Exact change:** Store claim-to-passage evidence with entity, value, unit, period, modality, and attribution. Validate headline, summary, body, and key facts against that evidence. Preserve disagreeing figures unless a supported revision explains them. Scale article length to available evidence; require useful context, uncertainty, and next developments where supported.
- **Acceptance test:** Catch a correct number attached to the wrong company/year, an unsupported date, a denial presented as fact, and conflicting casualty counts. A sparse dossier produces a concise complete article without repeated padding.
- **Effort:** L.
- **Risk:** Overstrict matching may reject legitimate paraphrases.
- **Dependencies:** P02, P06.

### P08 — Implement the missing knowledge-verification consumer

- **Why / evidence:** `B/knowledge/kb/llm/queue.py` queues work; `graph/facts.py`, `graph/storylines.py`, `graph/importance.py`, and `maintain.py` enqueue contradiction, causal, fact-verification, and entity-resolution tasks. No consumer for `kb.llm_tasks` was found in `B/src`.
- **Exact change:** Add a single-concurrency, leased consumer with typed handlers, evidence-version deduplication, bounded retries, expiry, and dead-letter reasons. Start with fact-verification and contradiction assessments. Store cited assessments separately from underlying assertions; keep uncertain causal links explicitly hypothetical.
- **Acceptance test:** Two workers cannot process one task concurrently; expired leases recover; quota deferral does not consume a failure attempt. Changed evidence schedules a fresh assessment. Failed verification cannot promote a claim.
- **Effort:** L.
- **Risk:** Model judgments could incorrectly alter graph meaning.
- **Dependencies:** P03, P05, P07.
- **Unattended restriction:** Entity merges and bulk graph corrections must remain proposals requiring human approval.

### P09 — Schedule discovery around coverage gaps and freshness

- **Why / evidence:** `B/src/news/world-source-discovery.service.ts` rotates countries by priority and last run. `B/src/kb/kb-corroboration.service.ts` prioritizes importance and recency. `B/src/youtube/event-videos.service.ts` records a `_searched` marker, preventing later discovery for an event.
- **Exact change:** Track source-to-publication conversion, extraction success, country/language/category coverage, and important unpublished events. Allocate bounded work to underserved areas and aging candidates. Give new outlets a monitored probation period. Replace permanent video-search suppression with TTLs and evidence-change triggers. Surface insufficient coverage without relaxing P01.
- **Acceptance test:** A synthetic backlog with one dominant topic still gives underserved categories bounded service. An initially video-empty event is searched again after its TTL. Broken feeds back off; recovered feeds re-enter rotation.
- **Effort:** M.
- **Risk:** Coverage balancing could delay urgent stories; retain an urgency lane.
- **Dependencies:** P03, P05, P06.

### P10 — Version evidence, articles, translations, and corrections

- **Why / evidence:** The dossier hash in `B/src/kb/kb-dossier.ts` omits ordinary document text changes. `B/src/kb/kb-editorial.service.ts` replaces article metadata on updates. `B/src/kb/kb-translation.service.ts` writes translations without checking whether the canonical article changed during translation.
- **Exact change:** Include content revisions in dossier fingerprints. Introduce immutable approved article versions and staged candidates. Bind translations to canonical-version hashes; validate citation sets, numbers, language, and paragraph completeness before attachment. Keep the prior approved version readable and expose dated correction/update notes.
- **Acceptance test:** Edit a source without changing its document ID: the fingerprint changes. Pause translation, publish a newer candidate, then resume: the stale translation cannot attach. EN/UK versions and corrections remain traceable; rejected articles stay rejected.
- **Effort:** L.
- **Risk:** Additional storage and migration complexity.
- **Dependencies:** P02, P07.
- **Unattended restriction:** Historical replacement or deletion is excluded; any bulk retrofit requires review.

**Batch exit:** Coverage improves through stronger evidence and scheduling, with versioned output available to existing clients.

## Batch 3 — Make mobile screens informative, fast to understand, and resilient

### P11 — Deliver a compact feed with stable pagination and real search

- **Why / evidence:** `B/src/news/news.controller.ts` repeatedly fetches from offset zero and slices ranked results; `feed.controller.ts` ranks a fixed pool. `M/App.tsx` searches only loaded items and stacks highlights, objectivity, top stories, videos, and radar above the list.
- **Exact change:** Introduce a compact feed DTO, bounded database queries, and cursor/snapshot pagination. Add server search over eligible articles, with clearly labeled local search offline. Reduce the initial header to one top-story module and collapsed secondary sections. Cards should show headline, concise explanation, update time, and independent-source count.
- **Acceptance test:** Concurrent new stories cause no duplicates/skips within a paging snapshot. Search finds an eligible article beyond the loaded page. At 360×800 and normal text size, the first story’s headline and summary appear without scrolling. Target ≤100 KB uncompressed JSON per 30-card page.
- **Effort:** L.
- **Risk:** Ranking changes may affect personalization.
- **Dependencies:** P01, P06, P10.

### P12 — Make the reader’s evidence inspectable without burying the story

- **Why / evidence:** `M/src/components/RichTextBlock.tsx` renders citations as plain text; sentence-based paragraph splitting can omit an unmatched trailing fragment. `M/src/app/news/[id].tsx` places several context blocks before the article. `M/src/app/event/[id].tsx` displays contradiction details as JSON.
- **Exact change:** Preserve all prose and render citations as accessible source controls. Lead with headline, summary, why it matters, and compact evidence status; move detailed context into expandable sections. Show disagreements as attributed alternatives. Label stock imagery as illustrative and Gemini video summaries as derived analysis; retain analyzed time ranges and distinguish transcript-verified quotations.
- **Acceptance test:** Every citation opens its correct source/passage; final fragments, decimals, and abbreviations survive rendering. A reader can inspect a dispute within two taps. Video analysis is never represented as a verified verbatim transcript or independent confirmation merely because it exists.
- **Effort:** L.
- **Risk:** Citation mapping and paragraph changes could alter navigation.
- **Dependencies:** P06, P07, P10, P11.

### P13 — Provide complete offline articles and explicit recoverable states

- **Why / evidence:** `M/src/app/news/[id].tsx` falls back to feed/bookmark data with `article: null`; `M/src/bookmarks.ts` stores feed-shaped items. `M/api.ts` permits three 24-second attempts and frequently collapses failures into empty/null results. The feed cache query in `M/App.tsx` omits several reader filters.
- **Exact change:** Cache bounded, versioned full articles and source metadata by ID/language/version. Distinguish saved summaries from complete downloads. Include all filters in cache identities. Add cancellation, request deduplication, a total interactive timeout, Retry-After handling, and typed loading/empty/offline/not-found/error states across reader, brief, event, entity, and topic screens.
- **Acceptance test:** A downloaded article reopens fully in airplane mode after restart. Corrupt/evicted caches recover safely. Switching filters or articles during a slow request cannot show stale results. A failed brief shows retry rather than “no news”; cached content appears within one second.
- **Effort:** L.
- **Risk:** Cache growth and migration of existing bookmarks.
- **Dependencies:** P10–P12.

### P14 — Complete EN/UK behavior, including fallbacks and plural forms

- **Why / evidence:** The 528 dictionary keys match, but `M/src/components/kb/kbUi.tsx` and `ExtraSourcesCard.tsx` keep separate dictionaries. `M/src/i18n/index.ts` can silently substitute original text or a summary for a translated body. Backend KB labels localize fields while event titles can remain in their original language.
- **Exact change:** Consolidate interface copy, accessibility labels, and errors into typed dictionaries. Add Ukrainian plural rules and locale-aware numbers, dates, and durations. Carry `requestedLanguage`, `contentLanguage`, and translation availability through APIs/caches. Label fallbacks and offer an explicit original-language action. Hydrate language before initial content requests.
- **Acceptance test:** EN/UK journeys through feed, reader, brief, event, entity, settings, and audio contain no unintended mixed-language controls. Test counts 1/2/5/21/22, midnight boundaries, unavailable translations, and rapid language changes. A summary never masquerades as a complete translated article.
- **Effort:** M.
- **Risk:** Existing fallback assumptions may hide missing translations.
- **Dependencies:** P10, P13.

**Batch exit:** Readers can quickly understand and verify stories, recover from failures, and read downloaded articles in either supported language.

## Batch 4 — Improve sustained phone performance, narration, and accessibility

### P15 — Reduce background work and expensive mobile rerenders

- **Why / evidence:** `M/App.tsx` fetches catalog, grants, games, graph, videos, and platform information after startup regardless of the active section. Feed rows render inline. Existing lint errors span state effects, unstable components, memoization, and ref usage.
- **Exact change:** Load secondary sections on demand; deduplicate shared context requests. Extract memoized feed rows and stable selectors, bound image dimensions, and defer below-fold enrichment. Resolve the existing lint errors without blanket suppression. Profile release builds using a repeatable low-end Android workload.
- **Acceptance test:** News startup sends no unrelated catalog/game/graph requests. Changing audio progress or a setting does not rerender every visible card. Across five cold launches and a 300-story scroll, target usable feed within three seconds on the defined network fixture, no blank rows, and memory returning within 15% of its post-load baseline.
- **Effort:** L.
- **Risk:** Lazy loading can introduce delayed section states.
- **Dependencies:** P11–P14.

### P16 — Keep narration faithful and invalidate stale audio

- **Why / evidence:** `B/src/news/audio-briefing.service.ts::audioCacheKey()` includes article ID and options, but no article version. `M/src/news-tts.ts` also caches by ID/language/options. `B/src/youtube/event-videos.service.ts` stores model-produced analysis as a `full` extracted document.
- **Exact change:** Bind scripts and audio to approved article/translation versions and a script hash. Generate briefings only from supported claims, preserving attribution, disagreements, and uncertainty. Declare whether playback is a brief or full reading; chunk full readings at sentence boundaries. Use language metadata rather than script-character guessing.
- **Acceptance test:** Correct an article: neither server nor phone serves old narration as current. EN/UK scripts preserve names, figures, denials, and uncertainty. Long readings complete without truncation, and model-derived video analysis cannot silently strengthen spoken certainty.
- **Effort:** M.
- **Risk:** Cache misses can increase generation demand.
- **Dependencies:** P03, P07, P10, P14.
- **Unattended restriction:** Adding provider secrets or activating billable TTS/storage requires human action.

### P17 — Make audio playback immediate, cancellable, and predictable

- **Why / evidence:** `M/src/news-tts.ts` waits for two 40-second server polls before fallback. It already has pause, seek, and queue support, but device speech is sliced to `Speech.maxSpeechInputLength`. `BriefingPlayerBar.tsx` exposes an adjustable seek bar without accessibility adjustment handlers.
- **Exact change:** Show ready/queued/playing/paused/failed states immediately. Offer device playback while natural audio prepares; never switch voices mid-sentence automatically. Cancel obsolete polling on stop or track change. Add sentence-chunked device speech, available speed controls, and documented interruption/background behavior using SDK 58-compatible APIs.
- **Acceptance test:** Ready audio starts within two seconds on the network fixture; queued playback offers device speech within two seconds. Stop during polling prevents later playback. Test calls/headphones, queue advancement, pause/resume, expired audio URLs, and complete long-script playback on Android and iOS.
- **Effort:** M.
- **Risk:** Platform audio-session differences and queue races.
- **Dependencies:** P13, P16.

### P18 — Finish accessibility, responsive layout, and theme consistency

- **Why / evidence:** `M/src/components/BriefingPlayerBar.tsx` has several adjacent controls; `NewsHero.tsx` has a hardcoded accessibility fallback. Reader/status styles include small text and local colors. `M/src/app/_layout.tsx` updates theme from stored settings on pathname changes. Reduced-motion support already exists in `VisualMotion.tsx`.
- **Exact change:** Standardize typography, contrast, focus order, control labels, selected/disabled states, and touch targets. Add seek increment/decrement accessibility actions and modal focus restoration. Support large text without fixed-height clipping. Share reactive theme settings across routes and preserve existing reduced-motion behavior.
- **Acceptance test:** Complete feed → article → source → report-error and audio journeys using TalkBack and VoiceOver. At 200% text size, 320-point width, landscape, and both themes, controls remain operable and text readable. Target 44-point iOS/48-dp Android controls and 4.5:1 normal-text contrast.
- **Effort:** M.
- **Risk:** Larger targets and text can require layout restructuring.
- **Dependencies:** P12, P14, P15, P17.

**Batch exit:** Release-device checks pass for performance, complete narration, screen readers, large text, dark mode, and interrupted/offline playback.
